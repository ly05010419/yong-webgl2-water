## 三、像素对齐验证

**前提**：源项目 `inkwell-webgpu-water` 的生产服务器跑在 `http://127.0.0.1:3200`；
本项目 `npx vite preview --port 4173 --strictPort`。

**场景**（1280×800、`deviceScaleFactor: 1`）：

| 名称 | 查询串 |
| --- | --- |
| `open-surface` | `scene=open&view=surface&mode=optimized&fixedTime=8.25&frames=240&ui=0` |
| `shore-surface` | `scene=shore&view=surface&mode=optimized&fixedTime=8.25&frames=240&ui=0` |
| `open-underwater` | `scene=open&view=underwater&mode=optimized&fixedTime=8.25&frames=240&ui=0` |

**两个必要条件**（缺一个就会出现假阳性）：

1. **等到渲染循环停下再截图。** `frames=240` 会让循环在第 240 帧后自己停下，
   指标随之冻结；脚本轮询 `getMetrics()` 直到两次快照完全一致。早期用固定
   `waitForTimeout(900)` 时两页停在不同帧上，近岸场累积状态不同，
   在开阔场景会掉出约 2.6 万个高光像素的差异。
2. **拦掉源项目的 `**/models/**` 请求。** 源演示页还会画一艘 glTF 帆船
   （约 2.6 万像素的船体轮廓，见下），本项目按设计不含船体。拦下模型下载后
   源引擎把船体当作缺失的可选布景跳过，两边渲染的就是同一个场景。
   源仓库不需要任何改动。

**结果**：三场景 `mismatch=0`、`maxΔ=0`（pixelmatch `threshold: 0`）。

## 四、交互回归

`scripts/interaction-smoke.mjs` 在 4 组视口（1280×800 → 900×620 → 1440×900 →
1280×800）下，每组顺序调用 23 次桥接 setter，覆盖
`setScene`（含重建近岸场）、`setSimulationResolution`、`setRenderScale`（含重建帧目标）、
`setLong/MediumCascadeScale`（含级联上传）、`setMode`、`setView` 以及六个纯 uniform 项，
最后 `resetMetrics()`。

判定：`getMetrics().error === null`、`ready === true`、无 `console.error`、无 `pageerror`。

**结果**：92 次 setter + 4 次 resize 后全部通过，`adapter` 为
`WebGL2 · ANGLE (Apple, ANGLE Metal Renderer: Apple M4, Unspecified Version)`。
